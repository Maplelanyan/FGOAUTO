# FGO 自动点击

FgoAuto 是 Windows 桌面程序，使用本机管理的 Android 14 Google Play 模拟器运行游戏。模拟器通过 Android Emulator gRPC 接口传输屏幕帧和触控；运行游戏时不连接平板、雷电或其他外部设备。图片模板、规则套装和触发次数仍保存在 `%LOCALAPPDATA%\FgoAuto`。

## 首次启动模拟器

1. 启动 FgoAuto，分别打开并阅读 Android SDK 许可和 Google Play 条款；接受后勾选确认框。
2. 点“准备模拟器”。FgoAuto 会在 `%LOCALAPPDATA%\FgoAuto\android-runtime` 下载 Android Platform Tools、固定版本的 Android Emulator 和 Android 14 x86_64 Google Play 系统镜像。需要稳定网络和至少 8 GB 可用空间。
3. 点“启动模拟器”。启动前 FgoAuto 会检查 Windows 虚拟机加速是否可用，不会自行修改 BIOS 或 Windows 虚拟化设置。
4. 模拟器画面显示在右侧预览。首次启动后，可直接点击或拖动预览操作 Android、登录 Google Play 并安装/登录 FGO。游戏数据和账号不会从其他模拟器迁移。

模拟器默认后台运行，并使用主机 GPU 渲染。预览目标刷新率为 60 FPS；实际帧率受显卡驱动、主机负载和游戏画面影响。手动触控和自动点击都会使用预览对应的原始画面坐标。

### 画面性能与统计

- 可勾选“720p 游戏性能模式”，重启模拟器后生效。Android 和游戏实际渲染、传输、预览均降为 `1280 × 720 @ 187 dpi`，渲染像素量比 1080p 减少约 56%；关闭时恢复 `1920 × 1080 @ 280 dpi`。分辨率变化首次冷启动，不清空已安装应用和游戏数据，设置保存在 `video-settings.json`。
- 旧模板、框选和规则继续使用 1920 × 1080 逻辑坐标。720p 模式下模板缩小到实际画面匹配，命中位置映射回逻辑坐标，发送触控时再换算到实际设备尺寸；细小模板缩放后可能降低匹配度，需要在游戏中检查。
- 游戏配置关闭模拟摄像头、GPS 和麦克风，保留声音输出和游戏兼容组件。只更新 AVD 对应配置项，其他已有配置、账号和游戏存档不变。
- “OpenGL 游戏模式”关闭客体 Vulkan 功能，仍使用主机显卡加速，重启模拟器后生效。可用于对照排查卡顿或纹理异常；仅支持 Vulkan 的游戏需要取消此项。现有配置默认保留标准图形模式，切换模式首次冷启动，不清空游戏数据。
- 接收流只发布最新完整 RGB 帧；后台预览转换与识别分别读取快照，UI 最多保留一个显示回调。自动识别直接使用原始像素，每秒最多开始 20 轮，耗时较长时自动降低频率。识别不再进行 JPEG 压缩和解码，只有手动固定截图时编码 PNG。
- 预览显示“接收 / 绘制”帧率、各自最近 5 秒间隔的 P95，以及距上次收帧时间。绘制计数指控件提交 `DrawImage` 的新帧，不代表显示器扫描输出。每 5 秒将平均帧率、转换/复制/提交耗时和进程分配、GC 情况写入运行日志；静止间隔仍保留在会话统计中。源序号缺口和截图接收 FPS 都不能当作游戏自身 FPS。
- 60 帧对应约 16.7 ms 的帧间隔。应在持续动画或战斗中比较帧率和 P95；静止画面可能不产生新帧，显示“等待新画面”时不会用重复绘制充高计数。截图流不再设 10 分钟固定期限，停止模拟器时通过取消令牌结束。
- 手动拖动只保留最新的待发送位置；按下和抬起保序，过期手势不会在之后补点。失去指针捕获、切换到自动执行和停止模拟器时会清理旧输入。触控使用独立指针编号，避免迟到的手动抬起影响自动点击。
- 展开“性能诊断（仅本次运行）”，可以选择正常、暂停预览、暂停截图流、暂停识别、30 FPS 预览。暂停预览会停止颜色转换和 UI 上传，但保留原始截图与识别；30 FPS 只限制预览处理，仍接收完整截图流。暂停截图流不会停止 Android 或游戏，也不会用额外截图偷偷代替它；依赖截图的识别等待恢复。恢复时丢弃暂停前的待显示图和识别结果，静止画面会额外确认一次当前截图后才恢复手动触控。这些开关不写入 AVD 或规则配置。
- 性能日志每 5 秒包含拥有的 QEMU 进程及 FgoAuto 的 CPU/工作集/专用内存、全部触控 RPC 延迟、每轮识别耗时与近 5 秒识别墙钟占用。CPU 的 100% 指一个逻辑核心，识别墙钟占用不等于整机 CPU 利用率。暂停截图流时仍记录资源数据。

## 图片模板和规则套装

点“框选图片目标”，在预览上拖动选取按钮、图标或周围独特图案。框选时画面会固定，选区显示在预览中，保存后可修改目标名称。图片目标库由所有套装共用；删除目标会同时移除所有套装对它的引用。

套装可新建、改名、复制和删除。规则没有先后顺序：FgoAuto 持续检查当前画面，匹配到可执行目标时先复核最新画面，再发送触控。可使用普通单点、列表最上方、普通指令卡和宝具卡执行方式。多条普通规则同时匹配时，优先执行匹配分数较高的一条。

普通指令卡规则可从五个卡位中随机选出三张，每张最多点一次；配置宝具卡规则后优先选宝具，再用普通卡补足三张。每条规则都可单独配置触发次数上限；留空为无限，任何一条达到设定上限都会停止整套流程。每次开始时触发计数归零。

匹配阈值默认 `0.82`，可在规则设置中修改。保存全部套装后，规则、阈值和触发次数会写入 `%LOCALAPPDATA%\FgoAuto\rule-sets.json`。现有 `%LOCALAPPDATA%\FgoAuto\templates` 图片素材和规则文件会继续沿用。

## 画面复核与故障处理

预览和识别共用模拟器 gRPC 截图流中的最新帧，旧帧不会排队执行。每次自动点击前都会重新取帧，确认画面仍属于同一场景、模板仍在原位置附近，再按坐标触控；切场景、目标移动或画面过期时会取消这次点击并重新识别。

模拟器启动失败时查看状态栏和运行记录。可以停止后重新启动；关闭 FgoAuto 时会请求模拟器正常关机，超时才结束由 FgoAuto 启动的模拟器进程。运行日志保存在 `%LOCALAPPDATA%\FgoAuto\logs`。

## 固定版本

- Android Emulator：`37.2.13`
- Android Platform Tools：准备模拟器时下载稳定版，并将 revision 记录到运行清单
- Android 系统镜像：`android-34 / google_apis_playstore / x86_64`，revision `14`
- 默认显示：`1920 × 1080 @ 280 dpi`

运行时版本记录在 `%LOCALAPPDATA%\FgoAuto\android-runtime\runtime-manifest.json`。FGO 能否在该镜像上安装并长期稳定运行，需要在用户自己的模拟器环境中实测；应用不会自动登录或操作 Google 账号。

## 本地回归检查

运行 `dotnet run --project tests/FgoAuto.PerformanceChecks -c Release`，检查慢触控发送下的移动合并、释放和取消，以及帧统计时间窗口、图片方向、模板坐标和切场景保护。检查不启动模拟器、不发送游戏触控，也不读取或改写用户规则。

追加 `-- --benchmark-transport --benchmark-recognition` 可测复制与 32 查询合成识别开销。这是客户端微基准，不代表游戏帧率。

实际窗口对照工具见 [PerformanceProbe](tools/PerformanceProbe/README.md)，本轮硬件与 ABI 证据见 [模拟器审计](docs/emulator-audit.md)，结论与复现记录见 [性能报告](docs/performance-analysis-20261115.md)。
